# 고객용 월간 리포트 설계

작성 2026-10-01 · 대상 JCC-CCM 서버·대시보드

## 1. 목표

매달 고객사별로 지난달 성과 문서를 **발행 시점 스냅숏**으로 남긴다(발행 뒤 데이터 정리·보존 삭제가 있어도
문서는 그대로 — 계약 갱신 증빙). 결정(사용자): 화면에 보관 + 알림. 알림은 실제 문자가 나가므로
**고객사별로 JCC가 켠 경우만**(기본 꺼짐).

## 2. 내용 (결과 언어)

1. 표지: 고객사·기간(지난달 1일~말일, 한국 시간)·판넬 수·발행일
2. 핵심 성과: 사고 징조 먼저 잡음(막음·도달·평균 선행) · 벤트 자동 작동 · 위험 경보 수·확인까지 평균 시간 ·
   자가복구(성공률) · 가동률(CCM 침묵 경보 구간으로 계산, 설치 전 기간 제외)
3. 판넬별 표: 가동률 · 위험/주의 경보 · 예지 감지 · 출력 작동 실패 · 최근 설치 점검 판정
4. 주의가 필요한 장비 Top
5. 다음 달 권고(자동): 드리프트 → 교정, 고착 → 센서 점검, 작동 실패 → 구동기 점검, 침묵 → 네트워크·전원,
   위치 스위치 없음(설치 점검 기록) → 보조접점 구동기 권장, 문제 없음 → "특이사항 없음"

## 3. 운영

- 감시 루프가 매시간 확인: 한국 시간으로 달이 바뀌었으면 고객사마다 지난달 리포트를 발행(이미 있으면 건너뜀).
- JCC: 고객사·월을 골라 "지금 발행"(재발행 — 이번 달 중간 확인도 가능, 같은 고객사·월은 교체).
- 알림(켠 고객사만): 그 고객사 알림 번호로 문자 한 통 "N월 리포트가 준비됐습니다". 알리고 미설정이면 생략.
- 저장: `monthly_reports(customer_id, period 'YYYY-MM', created_at, by, report_json)` 고객사·월 유일.

## 4. 권한

`GET /api/monthly` = read(고객은 자기 고객사만, JCC는 전부·고객사 필터) · `POST /api/monthly/issue` = admin ·
`POST /api/admin/monthly_notify` = admin(계정 관리의 고객사별 스위치).

## 5. 테스트

기간 경계(한국 시간 월초) · 지표(징조·벤트·경보·확인 시간·가동률·작동 실패) · 다른 고객사 데이터 제외 ·
권고 문구 · 자동 발행 1회만(재실행해도 중복 없음) · 알림은 켠 고객사만(발송 함수 가로채 실제 발송 없음) · 권한.
