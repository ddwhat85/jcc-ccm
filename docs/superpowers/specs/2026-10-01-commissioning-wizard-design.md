# 현장 설치 점검 마법사(시운전) 설계

작성 2026-10-01 · 대상 JCC-CCM 서버·대시보드·CCM 보고

## 1. 목표

장비가 도착한 날 설치 기사가 휴대폰으로 판넬 하나를 골라 순서대로 확인하고, 결과를 **시운전 기록**으로 남긴다.
결정(사용자): 마법사는 **점검·안내·보고서**까지. 설정 변경(배선·CCM 설정 파일)은 기사가 직접.

## 2. 단계

| 단계 | 확인 | 재사용 |
|---|---|---|
| 1 연결 | 판넬의 CCM 모두 온라인·센서 수신, 현장 예지(엣지 보고) 켜짐 | `diagnose(dev)`, `edge_state()` |
| 2 센서 | 센서마다 수신·값 유효·범위·고착·식별 — 값이 충분히 쌓이기 전(표본 6개 미만)은 '관찰 중' | `diagnose(dev, key)` |
| 3 예지 역할 | 화재(가스 1종 이상)·접점(전류+접점온도+함내온도)·결로(함내온도+습도) 가능 여부, CCM 설정 역할과 서버 판정 비교 | `inputs.roles_from_kinds`, 엣지 보고 `roles` |
| 4 출력 시험 | 벤트·히터·팬: 켜기→작동 확인→끄기→작동 확인→자동 복귀 | 수동 명령 대기열, ActuatorGuard 확인 상태 |
| 5 완료 | 전 단계 스냅숏 + 기사·메모 → 시운전 기록(합격/조건부/불합격), 인쇄·PDF | — |

항목 판정: `pass` · `warn` · `fail` · `wait`(관찰 중·시험 중) · `skip`(해당 없음). 실패·주의 항목엔 **할 일**(예: "센서 전원·RS485 배선·Modbus 주소 확인")을 붙인다.

## 3. 출력 시험 (서버가 단계 진행)

`POST /api/commission/output_test {panel, actuator}` → 판넬의 그 출력을 가진 현장 CCM에 수동 켜기 명령.
이후 점검 조회(`GET /api/commission/check`, 화면이 2초마다)가 상태를 진행한다:
`on_sent` → CCM 보고가 켜짐·confirm ok → `off_sent`(끄기 명령) → 꺼짐·ok → 자동 복귀 → `pass`.
confirm fault → `fail`(사유), 확인 장치 없음(confirm off) → 명령 반영만 확인하고 `warn`("릴레이만 확인 — 위치 스위치 권장"),
시간 초과(작동 시간 × (재시도+1) + 30초, 최대 150초) → `fail`("CCM 응답 없음"). 실패해도 끝에는 항상 자동 복귀 명령.
화면은 누르기 전 "판넬 앞에 사람이 있습니다" 확인을 받는다(실제 설비가 움직임).

## 4. 기록·권한

- `commission_reports(id, panel, ts, by, overall, report_json)` · 이벤트 `commission`.
- 경로: `GET /api/commission/check`·`POST /api/commission/output_test`·`POST /api/commission/complete` = admin,
  `GET /api/commission/reports` = read(고객은 자기 판넬 보고서만 — 설치 품질 증빙).
- 판정 합격 = fail 0·wait 0 / 조건부 = fail 0, warn 있음 / 불합격 = fail 있음(완료는 가능, 표시).

## 5. CCM

엣지 보고에 `roles: {역할: 센서키}` 추가(설정 파일 [predict.roles]) — 서버가 CCM 설정과 서버 판정 차이를 알려 준다.

## 6. 화면

도구 → 설치 점검(admin): 판넬 선택 → 단계 카드(상태·항목·할 일) → 출력 [시험] → [완료 기록] → 보고서(인쇄).
도구 → 설치 보고서(모두): 범위 안 판넬의 기록 목록·열람·인쇄. 휴대폰 폭 우선.

## 7. 테스트

판정 규칙 단위(센서 할 일 매핑·역할 가능 여부·CCM 역할 불일치·출력 시험 상태기계·시간 초과·자동 복귀) ·
종단(실제 HTTP + 가상 CCM): 설치 점검 → 벤트 시험 합격 → 걸림 주입 시 불합격 → 완료 기록 → 고객 계정 열람 가능·타 고객 불가.
