# 고객사별 계정 분리 설계

작성 2026-09-30 · 대상 JCC-CCM 서버·대시보드

## 1. 목표

지금은 공용 계정 하나(환경변수)로 로그인하면 모든 판넬이 보인다. 고객사가 둘만 돼도 A사가 B사를
본다. 고객사 → 판넬 구조와 계정 등급을 만들고, **모든 데이터 API가 계정의 고객사 판넬만** 돌려주게 한다.

결정(사용자): 계정은 JCC만 발급 · 고객 계정은 담당자 / 보기 전용 두 등급.

## 2. 등급

| 등급 | 범위 | 할 수 있는 것 |
|---|---|---|
| `admin` (JCC 관리자) | 전체 | 전부 + 계정 관리 · 튜닝 · 탐색·배선 · OTA · 자가치유 · 센서 설정 · 판넬 이름 · 진단 · 알림 테스트 |
| `manager` (고객 담당자) | 자기 고객사 판넬 | 보기 · 경보 확인(ack) · 벤트·히터·팬 수동 조작 · 리포트 |
| `viewer` (고객 보기 전용) | 자기 고객사 판넬 | 보기 · 리포트 |

환경변수 계정(JCC_DASHBOARD_USER/PW)은 **비상용 admin**으로 유지(기존 운영 무중단). DB 계정이 없어도 동작.

## 3. 데이터

- `customers(id, name, created_at)` · `panel_owner(panel PK, customer_id)` — 배정 안 된 판넬은 admin만 봄.
- `users(id, username UNIQUE, pw_hash, role, customer_id, must_change, disabled, created_at)` —
  pw_hash = PBKDF2-SHA256(200,000회, 16바이트 솔트). 복원 불가.
- `sessions(token_hash PK, user_id, created_at, expires_at)` — 쿠키엔 32바이트 난수, DB엔 SHA-256만.
  7일 만료. 비번 변경·초기화·계정 끄기 → 그 사용자 세션 전부 삭제(즉시 로그아웃).
- `customer_receivers(customer_id, number)` — 고객사 알림 번호.

## 4. 권한 표 (서버의 단일 정책)

`ROUTES = {(메서드, 경로 패턴): 정책}` — 정책 ∈ `public`(로그인 불필요) · `read`(모든 등급, 범위 필터) ·
`operate`(admin·manager, 범위 확인) · `admin`. **표에 없는 경로는 403.** 테스트가 서버의 모든 경로가 표에
있는지, 고객 계정으로 다른 고객사 데이터가 새지 않는지 확인한다.

범위 필터(read): 판넬·기기·경보·사건·이벤트·예지·리포트·이력은 계정 고객사의 판넬(→ 그 판넬 CCM)만.
operate: 대상 판넬/경보가 범위 밖이면 403. 기기 텔레메트리(`/v1/telemetry`)·OTA 다운로드는 기존 기기 키.

## 5. 화면

- 로그인: 기존 터미널 로그인 그대로, DB 계정 지원. `must_change`면 로그인 직후 비번 변경 창(건너뛰기 불가).
- `/api/auth/status` → `{enabled, authed, user, role, customer}`. 등급에 따라 JCC 전용 메뉴 숨김.
- 계정 관리(admin, 도구 메뉴): 고객사 추가 · 판넬 배정(드롭다운) · 알림 번호 · 계정 추가(등급 선택) →
  **임시 비번 한 번만 표시** · 비번 초기화 · 끄기/켜기. 모든 사용자: 내 비번 변경.
- 수동 조작·경보 확인 기록에 사용자 이름.

## 6. 알림

경보 → 그 기기의 판넬 → 고객사 알림 번호 + 환경변수 JCC 운영 번호(중복 제거)로 발송. 알리고 키는 여전히 환경변수.

## 7. 범위 밖

고객사별 기기 전송 키 · 2단계 인증 · 고객 자가 가입 · 고객 관리자가 직원 계정 발급.

## 8. 테스트

비번 해시·검증(틀린 비번·끈 계정·만료 세션) · 로그인 잠금 유지 · 권한 표 커버리지(모든 경로 분류) ·
고객 A 계정으로 B의 판넬·기기·경보·사건·이벤트·예지·리포트·이력이 안 보임 · viewer 조작 403 · manager 범위 밖 조작 403 ·
비번 변경 시 다른 세션 무효 · 임시 비번 강제 변경 · 알림 수신 번호 합성 · 환경변수 admin 하위호환(기존 test_auth 통과).
