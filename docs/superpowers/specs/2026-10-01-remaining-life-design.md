# 남은 수명(여유) 예측 — 설계

## 목적

지금 예지보전은 "지금 위험한가"를 본다. 여기에 "이대로 가면 언제 위험해지나"를 더한다.

- 접점 발열: 잔차(예상보다 더 뜨거운 정도)가 날마다 조금씩 오르면 → "위험 기준(11°C)까지 약 9주"
- 센서 드리프트: 가스 센서 기준선이 서서히 오르면 → "경고선까지 약 20일 — 교정 필요"
- 그 밖의 아날로그 센서(온도·습도 등): "경고선 도달까지 약 N일"

## 원칙

- **모르면 모른다고 한다.** 하루 대표값이 7일 미만이면 예측하지 않고 "데이터 N일 — 7일 쌓이면 예측".
  추세가 분명하지 않으면(기울기 범위가 0을 포함) "뚜렷한 추세 없음".
- **범위로 말한다.** 한 점 예측 대신 "약 20일 (14~35일)".
- **경보가 아니다.** 문자를 보내지 않는다. 화면·활동 기록·AI 답·월간 리포트 권고에만 쓴다.
  14일 이내로 들어오면 활동 기록에 한 번 남긴다(같은 항목은 7일에 한 번).
- 출력 결정에 쓰지 않는다(설명·계획용).

## 계산

- 하루 대표값 = 그날(한국 시간) 값의 **중앙값** — 순간 튐에 강하다.
  - 센서: readings에서 시간마다 오늘·어제를 다시 집계(보존 기간 14일 안에서 굳힌다)
  - 접점 잔차: 예지 판정 주기마다 잔차를 모아 시간마다 그날 중앙값 저장(재시작 시 표본이 더 많은 쪽 유지)
- 표 `rul_daily(metric, day, value, n)` — 1년 보관. metric = `contact:{panel}` 또는 `sensor:{dev}:{key}`
- 추세 = 최근 30일 **Theil–Sen**(모든 두 점 기울기의 중앙값). 범위 = 기울기 25~75 백분위.
- 남은 날 = (기준 − 오늘 추세값) / 기울기. 범위는 기울기 범위로. 365일 넘으면 "1년 넘게 여유".
- 기준: 접점 = 활성 튜닝의 `contact.res_alarm`, 센서 = 경고(warn)값, 없으면 경보 상한(max), 하한만 있으면 아래 방향.
  0/1만 나오는 센서(도어·연기 등)는 제외.

## 구성

| 단위 | 하는 일 |
|---|---|
| `server/jcc_server/rul.py` | `theil_sen`, `estimate`, `rollup(storage, now)`, `panel_view(storage, panels)` |
| `storage.py` | `rul_daily` 표, 예지 판정 때 잔차 표본 모으기 |
| `monitor.py` | 시간마다 `rollup` |
| `app.py` | `GET /api/rul`(read, 범위 필터) |
| `ai.py` | 도구 `remaining_life(panel)` |
| `monthly.py` | 60일 이내 항목을 다음 달 권고에 |
| `index.html` | 예지보전 상자에 "남은 여유" 최대 3줄 |
| `demo-api.js` | 시연용 21일 합성 기록으로 같은 모양 |

## 시험

- Theil–Sen: 직선·잡음·이상치 몇 개에도 기울기 유지
- estimate: 데이터 부족·추세 없음·멀어짐·이미 넘음·1년 넘음·정상 예측(범위 포함)
- rollup: readings → 하루 중앙값, 재집계 시 덮어쓰기, 접점 표본 n 규칙
- API 범위(고객은 자기 판넬), 14일 이내 기록 한 번만
