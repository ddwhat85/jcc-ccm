# JCC-CCM 배포 · 알림 설정 안내

## 1. 운영 서버 올리기 (Render) — 휴대폰으로도 됨

저장소의 `render.yaml`이 운영 설정을 담고 있다(Starter + 영구 디스크 + 운영 잠금).
**요금**: Starter 월 약 $7 + 디스크 1GB 월 약 $0.25. 무료 플랜은 재시작 때 DB가 지워져
계정·월간 리포트·설치 점검 기록이 사라지므로 운영엔 쓰지 않는다(시연은 데모 아티팩트로).

### 0) 먼저 — 저장소를 비공개로 (권장)

GitHub 앱/웹 → `ddwhat85/jcc-ccm` → **Settings** → 맨 아래 **Danger Zone** →
**Change visibility** → **Make private**. 판매용 펌웨어·예지 알고리즘 코드가 공개돼 있기 때문.
비공개여도 Render 연결은 된다(아래 2번에서 저장소 접근만 허용).

### 1) 가입·연결

1. <https://render.com> → **Get Started** → **GitHub로 가입**
2. GitHub 권한 요청 → **Only select repositories** → `jcc-ccm` 선택 → **Install / Authorize**
3. 결제 카드 등록(Starter 플랜용) — Render 화면 **Billing**

### 2) 서버 만들기

1. Render 대시보드 → **New +** → **Blueprint**
2. `ddwhat85/jcc-ccm` 선택 → `render.yaml`을 읽어 **jcc-ccm (Starter, 디스크 1GB)** 가 표시됨
3. 입력란이 뜨면:
   - `JCC_DASHBOARD_USER` — 비상 관리자 아이디(예: `jcc-ops`)
   - `JCC_DASHBOARD_PW` — **긴 비번**(14자 이상, 다른 곳에서 안 쓰는 것). 어디에도 적어 두지 말고 비번 관리 앱에.
   - 알리고·웹훅 칸은 **비워 둬도 된다**(나중에 넣음)
4. **Apply** → 3~5분 빌드 → `https://jcc-ccm-xxxx.onrender.com` 주소가 생긴다

`JCC_API_KEY`(CCM 기기 키)는 Render가 무작위로 만든다. 서비스 → **Environment** →
`JCC_API_KEY` 값 보기 → 복사해 각 CCM의 `config.toml`에 넣는다:

```toml
[transport.http]
url = "https://jcc-ccm-xxxx.onrender.com/v1/telemetry"
api_key = "(복사한 값)"
```

### 3) 첫 로그인과 계정

1. 주소 접속 → 터미널 로그인 화면 → 비상 관리자 아이디·비번
2. **도구 → 계정 관리** → 고객사 추가 → (CCM이 붙은 뒤) 판넬 배정 → 담당자 계정 추가
   → 임시 비번을 담당자에게 전달(첫 로그인 때 본인이 바꾼다)
3. 직원용 JCC 관리자 계정도 여기서 만든다(비상 계정은 평소에 쓰지 않는다)

### 운영 잠금이 하는 일 (`JCC_REQUIRE_AUTH=1`)

- 비번을 빠뜨려도 **누구나 들어오는 서버가 되지 않는다** — 아무도 못 들어오는 잠긴 서버가 된다.
- 기기 키가 없으면 CCM 데이터를 받지 않고 "JCC_API_KEY를 설정하라"고 답한다.

### 바꾸면 안 되는 것

- `JCC_DB=/var/data/jcc.db`, `JCC_OTA_DIR=/var/data/ota` — 영구 디스크 경로. 바꾸면 데이터가 사라진 것처럼 보인다.
- 비상 비번을 바꾸면 그 계정으로 로그인된 화면은 모두 다시 로그인해야 한다(정상).

### 데이터 백업 (월 1회 권장)

Render 서비스 → **Disks** → **Snapshots**(Render가 매일 자동 스냅숏을 남긴다). 복원도 여기서.

### 자가치유 (자동 복구)

문제를 감지만 하지 않고 안전한 선에서 스스로 복구한다. 두 단계로 동작한다.

**L1 — 채널 재시작**: 센서 채널이 **침묵(silent)** 하거나 **고착(stuck)** 되면
그 채널만 재시작한다(가장 안전한 조치라 먼저 시도).

**L2 — CCM 재시작**: ① CCM이 **통째로 침묵**하거나 ② L1이 포기한 채널이면,
그 CCM을 통째로 재시작한다. 효과는 크지만 그 CCM 아래 전 센서가 잠깐 끊기므로
상한을 더 엄격히 둔다(재시도 적게·쿨다운 길게).

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `JCC_AUTOHEAL` | `1` | `0`이면 자가치유 전체를 끈다. |
| `JCC_HEAL_MAX_RETRY` | `2` | L1 장애당 최대 채널 재시작 횟수. |
| `JCC_HEAL_COOLDOWN` | `60` | L1 같은 센서 재시도 간격(초). |
| `JCC_HEAL_DAILY_CAP` | `30` | L1 하루 채널 재시작 총량. |
| `JCC_AUTOHEAL_L2` | `1` | `0`이면 L2(CCM 재시작)만 끈다(L1은 유지). |
| `JCC_HEAL_L2_MAX_RETRY` | `1` | L2 CCM당 최대 재시작 횟수(재부팅은 무겁다). |
| `JCC_HEAL_L2_COOLDOWN` | `180` | L2 같은 CCM 재시도 간격(초). |
| `JCC_HEAL_L2_DAILY_CAP` | `10` | L2 하루 CCM 재시작 총량. |
| `JCC_HEAL_L2_ON_CHANNEL_FAIL` | `1` | `0`이면 'L1 실패 → CCM 재시작' 승격을 끈다. |

- 드리프트·이상은 보정/공정 문제라 자동 재시작 대상이 아니다(사람 판단 영역).
- 재시도 상한을 넘으면 포기하고 사람에게 넘긴다(→ 상향·알림).
- 사람이 확인(ack)한 경보는 자동개입을 멈춘다(사람 우선).
- 모든 개입은 로그로 남는다: L1 `heal_restart`·`heal_ok`·`heal_giveup`,
  L2 `heal2_restart`·`heal2_ok`·`heal2_giveup`.
- **참고**: `L2_ON_CHANNEL_FAIL`을 켜면 센서 채널 하나가 L1으로 안 풀릴 때 그 CCM을
  통째로 재부팅한다 → 그 CCM의 다른 센서도 잠깐 끊긴다. 이 부작용이 싫으면 `0`으로
  꺼면 L2는 'CCM 전체 침묵'일 때만 동작한다(그때는 어차피 다 죽어 있어 잃을 게 없다).

## 2. 카카오 알림톡 · 문자 연결

경보를 담당자 휴대폰으로 보낸다. 제공업체는 **알리고(Aligo)** 기준.

### 준비 (알리고 쪽에서 미리 해둘 것)

1. <https://smartsms.aligo.in> 가입 (사업자등록증 필요)
2. **발신번호 등록** — 회사 번호를 등록하고 승인받는다 (문자·알림톡 공통)
3. 문자만 쓸 거면 여기까지. **알림톡**도 쓰려면:
   - 카카오톡 채널 개설 → 알리고에 **발신프로필(senderkey)** 연결
   - **알림톡 템플릿 등록 후 카카오 심사 통과** (보통 1~2영업일)
   - 템플릿 본문에 변수를 넣어 승인받는다. 예:
     ```
     [JCC-CCM] #{severity} 경보
     장비: #{device}
     내용: #{detail}
     시각: #{time}
     ```
4. 알리고 **API Key**와 **사용자 ID** 확인 (마이페이지)

### Render에 키 넣기

Render 대시보드 → 서비스 선택 → **Environment** → 아래 값 입력 후 저장
(저장하면 자동 재배포된다). **키는 절대 코드/깃허브에 넣지 말 것.**

| 환경변수 | 설명 | 예시 |
|---|---|---|
| `JCC_ALIGO_KEY` | 알리고 API Key | `abcd1234...` |
| `JCC_ALIGO_USER` | 알리고 사용자 ID | `jccsolution` |
| `JCC_ALIGO_SENDER` | 등록된 발신번호 | `0212345678` |
| `JCC_ALIGO_RECEIVERS` | 수신번호(쉼표로 여러 명) | `01011112222,01033334444` |
| `JCC_ALIGO_SENDERKEY` | 카카오 발신프로필 키 (알림톡만) | `xxxxxxxx` |
| `JCC_ALIGO_TPL` | 승인된 템플릿 코드 (알림톡만) | `TJ_0001` |
| `JCC_ALIMTALK_TEXT` | 승인 템플릿과 **똑같은** 본문 틀 | 위 예시 문구 |

- `SENDERKEY` + `TPL` 을 넣으면 **알림톡**으로 발송되고, 실패 시 **문자로 자동 대체발송**된다.
- 둘을 비워두면 **문자(SMS/LMS)** 로만 발송된다. (90바이트 초과 시 자동 LMS)
- `JCC_WEBHOOK` 에 URL을 넣으면 슬랙·사내 서버로도 같이 보낸다.

### 연결 확인

대시보드 상단 **도구 → 알림 테스트 발송**을 누르면 테스트 메시지 1건이 실제로 나간다.
상태 표시줄에 성공한 채널이 표시된다. (채널 미설정이면 발송되지 않고 안내만 뜬다)

### 언제 발송되나

| 상황 | 발송 |
|---|---|
| 위험(crit) 경보 발생 — 임계값 초과, CCM/센서 침묵 | 즉시 |
| 경보를 일정 시간 확인(ack) 안 함 | 상향(에스컬레이션) 후 재발송 |
| 주의(warn) — 고착·드리프트·이상 조기감지 | 화면·로그에만 (문자 안 감) |

발송 시간은 `JCC_ESCALATE_AFTER`(초)로 조정한다. 기본 120초.

## 3. AI에게 물어보기 켜기 (선택)

대시보드 **도구 → AI에게 물어보기**, 경보 옆 **AI 해설**. Claude가 경보·활동 기록·센서 추세를
직접 조회해 답하고, 답마다 살펴본 기록을 근거로 붙인다. AI는 설명만 한다 — 벤트·히터·팬 결정은
지금처럼 검증된 규칙이 하고, AI에게는 장비를 움직이는 도구가 없다.

### 켜는 순서

1. <https://console.anthropic.com> 에서 API 키 발급(결제 수단 등록 필요) — 사장님이 직접
2. Render 서비스 → **Environment** → `ANTHROPIC_API_KEY`에 붙여넣기 → 저장(자동 재시작)
3. 대시보드 **도구 → 계정 관리** → 고객사 선택 → **AI에게 물어보기 사용** 체크

### 꼭 알아 둘 것

- **데이터가 외부로 나간다.** 질문할 때 그 고객사 판넬의 경보·기록·센서값이 Anthropic으로 전송된다.
  그래서 고객사별 스위치는 **기본 꺼짐**이다. 계약서·고객 동의를 확인한 고객사만 켠다.
  꺼진 고객사 판넬은 JCC 관리자가 물어도 보내지 않는다.
- **비용 상한**(폭주 방지용 안전장치): JCC 직원 전체 월 `JCC_AI_STAFF_LIMIT`(기본 1000회),
  고객사별 월 `JCC_AI_MONTHLY_LIMIT`(기본 200회). 넘으면 그 달은 막힌다.
  대시보드 물어보기 창 아래에 이번 달 사용량이 보인다. 실제 요금은 Anthropic 콘솔에서 확인.
- 키가 없거나 패키지(`anthropic`)가 없으면 이 기능만 꺼지고 서버의 나머지는 그대로 돈다.
- 경보 문자 발송은 AI를 기다리지 않는다(AI 응답이 늦거나 실패해도 경보는 그대로 나간다).
- AI가 켜진 고객사는 월간 리포트 맨 위에 **AI 해설**(3~5문장)이 붙는다. 리포트에 없는 숫자가 나오면
  해설을 버리고 리포트만 발행한다. 해설도 그 고객사 월 질문 한도에서 1회로 센다.
